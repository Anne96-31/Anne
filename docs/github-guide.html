Copilot 怎麼用

Copilot 有兩種模式：Ask 只回答問題、不改任何東西，適合學習；Agent 會實際修改程式並開 PR。新手建議先多用 Ask。以下是在各頁面的用法，按鈕位置與名稱會依你的 Copilot 方案和 GitHub 改版而略有不同。

GitHub 首頁（Dashboard）

問任何關於 repo 的問題

  1. 在「Ask anything」輸入框旁，把模式選為 Ask。
  2. 點 All repositories，限定為 Anne96-31/Anne。
  3. 輸入問題，按送出。
可以這樣問這個 repo 每天的日報是怎麼產生的？請用新手看得懂的方式說明。
Code 分頁 · 開啟某個檔案

請 Copilot 解釋程式碼

  1. 打開 twdaily/screener.py。
  2. 點檔案右上角的 Copilot 圖示，或選取幾行程式後問 Copilot。
可以這樣問「低檔金叉」和「DIF翻正」的條件各是什麼？評分 0–7 分是怎麼算的？
Pull requests · 某個 PR

合併前先讓 Copilot 摘要

  1. 打開 PR，在右側 Reviewers 選 Copilot 請它審查。
  2. 或在 Copilot 對話中問這個 PR 的內容。
  3. 看完沒問題再按 Merge。
可以這樣問這個 PR 合併後，每天的排程和刪除規則會有什麼變化？有沒有風險？
Actions · 失敗的執行

看懂錯誤訊息

  1. 點紅叉的那次執行 → report → 展開紅色步驟。
  2. 點錯誤旁的 Copilot 按鈕（例如 Explain error），或把錯誤貼給 Copilot。
可以這樣問「同步到 Notion」這一步為什麼失敗？我需要在 Notion 或 Settings 改什麼？
Issues → Agents

讓 Copilot 動手改程式

  1. 新增 Issue，寫清楚要改什麼，例如「只列出評分 4 分以上的股票」。
  2. 在 Assignees 指派給 Copilot。
  3. 到 Agents 分頁看進度，它完成後會開 PR，你審查後再合併。
Issue 範例請把 twdaily/screener.py 的入選門檻改為評分 ≥ 4，並更新 tests/test_screener.py。

同一時間只讓一個 AI 改同一個分支。Copilot 和 Claude 都會開 PR，各自在自己的分支上工作就不會互相覆蓋。任何 PR 都先看過 Files changed 再合併，因為合併後的程式就是隔天早上 07:43 會自動執行的程式。

要看什麼，去哪裡

今天的日報 每天看

Notion「台股每日日報」資料庫，點最上面那列的標題 → OPEN。GitHub 上則是 Code → reports/latest.md。

workflow 的設定 想改排程時

Code → .github/workflows/daily-report.yml。排程時間在 cron，保存天數在 RETENTION_DAYS。

今天有沒有跑成功 沒更新時

Actions → 台股每日投資日報。最上面一筆是 ✅ 就是成功；沒有今天的紀錄就按 Run workflow 補跑。

選股邏輯與程式 想學習時

Code → twdaily/screener.py，或看系統架構圖上每個環節的程式碼。
